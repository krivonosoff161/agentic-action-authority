## Correction and boundaries

The 0.1.0 staging upload exposed an encoding defect in the release verifier,
not a changed wheel or an approval-core failure. Wheel METADATA is now decoded
strictly as UTF-8 before email-header parsing. Regression tests cover ASCII,
Unicode arrows, Cyrillic/Chinese text, invalid UTF-8 and genuinely changed text.
Index subject hashes and description equality remain required; no checks are
disabled and no old tag or uploaded artifact is replaced.

The approval mechanism, effect adapter and dependency versions are unchanged.
The optional adapter uses the published Harness 1.14.2 guarded writer. Core-only
installation still does not require Harness. One create-only UTF-8 file remains
the supported effect; this does not establish content truth, generic containment
or universal exactly-once semantics.

Both publication environments preserve their old exact v0.1.0 admission and add
only v0.1.1. Reviewer and branch protections are unchanged. A new tag-built wheel
passed core/adapter tests on Windows and Linux, TestPyPI, then PyPI with the
same bytes. The [0.1.0 failed staging record](v0.1.0.md) is retained separately.
