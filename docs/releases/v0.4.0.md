# 0.4.0 — optional Agent Framework document adapter

## Scope and publication boundary

This is the versioned release scope, not an upload receipt. Check the
[GitHub release](https://github.com/krivonosoff161/agentic-action-authority/releases/tag/v0.4.0)
and [PyPI package](https://pypi.org/project/agentic-action-authority/0.4.0/)
for completed publication and the exact wheel digest before installing:

```text
python -m pip install "agentic-action-authority[agent-framework]==0.4.0"
python -m pip check
```

Use `[harness]` for the existing file adapter without Agent Framework, or omit
extras for the approval core. Python 3.11 is the tested target; the current
platform locks cover Windows x64 and Linux x86_64 with glibc 2.28+.
The optional integration pins `agent-framework-core==1.23.0` and Harness 1.14.2.
It is an independent integration, not a Microsoft-maintained or endorsed package.

## Changes

- Adds `ash_action_authority.agent_framework.AgentFrameworkDocument` and the
  `agent-framework` extra. One declaration-only tool call supplies content only;
  the trusted host retains the final UTF-8 bytes and occurrence identity before
  detached operator approval. Changed occurrence/content refuses before approval
  is spent.
- Uses the existing `DocumentHost` and the single Harness create-only writer.
  No new writer, model-selected path, automatic signer or arbitrary-tool executor.
- Adds a real native Agent/Workflow and FileCheckpointStorage example with
  an explicitly scripted client and synthetic signer. A new workflow instance
  resumes from a checkpoint using readback after the effect; recovery does not
  invoke the writer again.
- Adds fourteen installed SDK tests on each supported OS. Release verification
  includes these lanes for the tag-built wheel and downloaded index bytes.
- Updates all five build/platform setuptools pins from 84.0.0 to 84.1.0 for
  [GHSA-xmj3-9gf7-h52w](https://github.com/pypa/setuptools/security/advisories/GHSA-xmj3-9gf7-h52w).
  The affected deprecated wheel-as-egg namespace path is not the documented
  PEP 517 build path. This maintenance is not a claim of a prior compromise.

## Compatibility and limits

Existing 0.3.0 core, `DocumentHost.execute_approved()` and content callback
interfaces remain available. No task-state migration, signature-domain change
or widening of file authority is introduced. Version 0.3.0 does not include
the new optional framework adapter; see the unchanged [0.3.0 record](v0.3.0.md).
Core installation and import do not require Harness or Agent Framework.

The host still owns key enrollment, same-occurrence routing, public-data
admission and checkpoint/state storage. Routing IDs are not authentication.
Declaration-only tools do not inherit SDK FunctionMiddleware/FIDES enforcement.
This adapter does not promise exactly-once workflow-response delivery,
cross-task deduplication, content safety, or containment of arbitrary host code.
An uncertain result remains uncertain and does not authorize replay.

Expected installed inventory per OS: core **33**, Harness **112** (including
core), and Agent Framework **14**. Zero skips, errors, failures or expected
failures are accepted. Counts are bookkeeping, not completed publication proof
or independent security scores. The native example uses synthetic approvals,
not human consent; no model/provider call or external pilot is claimed.
